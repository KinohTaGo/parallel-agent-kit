# parallel-agent-kit（日本語）

1 台の機械で複数のコーディングエージェントを並べて動かすための、試験つきの小さな部品集です。
**起動の門**（admission gate）・セッション間の**ファイルの受け箱**（mailbox）・**共有の git 作業ツリーの守り**の 3 つ。

[English README](../../README.md)

**状態:** 0.1.0。Python 3.9 以上の標準ライブラリだけ（macOS・Linux）。試験は pytest と bats。

## なぜ作ったか

1 つのエージェントが 1 つの checkout で働くのは簡単です。同じ機械で何体も、しかも同じ checkout で働かせると、
1 体では起きない壊れ方をします。全員が同時に起動して swap が埋まり全セッションが一緒に遅くなる、
セッション間の連絡が誰にも見せられないまま消える、あるエージェントの `git stash` が別のエージェントの書きかけを持ち去る、などです。

ここにある部品は、長く運用している複数エージェントの環境で**実際に起きた失敗**への直しを、小さく一般的な形に書き直したものです。
どの部品にも共通する決まりは 1 つです: **検査は「検査できなかった」と言えなければならない**。黙って通る検査は、誰も探しに行かないので最も高くつきます。

## 中身

| 部品 | 防ぐ失敗 | 入口 |
|---|---|---|
| 起動の門 | エージェントが一度に起動しすぎ、swap が埋まって全セッションが遅くなる | `python3 -m agentkit.gate check` / `hook` |
| 受け箱 | セッション間の便が誰にも見せられない／新しいセッションに古い便が押し寄せる | `python3 -m agentkit.mailbox send / inbox / show / mark` |
| 作業ツリーの守り | `stash`・`reset --hard`・`commit -a`・`--amend`・`pull --rebase` が他のエージェントの仕事を壊す・巻き込む | `python3 -m agentkit.worktree check` / `hook` |
| `safe-commit` | 他のエージェントが stage した file が自分の commit に入る | `bin/safe-commit -m MSG -- path...` |

### 起動の門（`src/agentkit/gate.py`）

* **圧力**（1 分の load を core 数で割った値・swap の使用率）と、機械全体の**起動の台帳**（JSON lines・排他の file lock）を読みます。
* 圧力で段を選び、段ごとに直近の時間窓の起動数に上限を掛けます（既定: 0.70 から 1 時間に 6・0.85 から 3・0.95 から 1・1.0 で 0）。
* **開いて通す、そしてそう言う。** 測りや台帳が読めないときは起動を許し、理由に「どれが読めなかったか」を書きます。門が壊れて全部が止まるほうが悪いからです。
* **swap の total が 0 は「swap が無い」であって「swap が足りない」ではない。** 再起動の直後に total 0・free 0 を返す系があり、それを「空きが閾値未満」と読んで全部の job を止めた実例があります。

### 受け箱（`src/agentkit/mailbox.py`）

* 便は JSON の file（mode 600）。宛先は `<lane>`・`<lane>#<session>`（8 字以上）・`all`。*lane* は役割や project で、1 つの lane を複数のセッションが受け持てます。
* **cursor は「床」で、しおりではない。** 床は「届けた」か「自分宛てでない」便が途切れずに続く所だけ進みます。飛ばした便があれば床はそこで止まり、「最後に読んだ所」の下へ落ちて消えることがありません。
* **覗くだけでは消費しない。** `--deliver` なしの `inbox` は何も変えません。`show <id>` で読んで `mark --as <reader> <id>` で読んだ物だけを記録します。`inbox --deliver` は書き出した後にだけ印を付けるので、`| head` が切った分は残ります（pipe の buffer に既に入った分だけは例外。正確な記録が要るときは show と mark で）。
* **新しいセッションは lane から始まる。** 0 からではない（古い便が押し寄せない）、「今」からでもない（その lane が誰も動いていない間に来た便も届く）。
* **時計のずれ:** id は UTC の時刻で始まります。読み手は床の 10 分下まで見返すので、時計が遅れている機械からの便も落ちません。
* 短い session の id は送る時に拒みます（短すぎる id が誰にも当たらず lane 全体へ配られた実例があります）。

### 作業ツリーの守り（`src/agentkit/worktree.py`）と `safe-commit`

* shell が走らせる**前**に命令の行を読み、共有の作業ツリーで害になる git の命令を報告します。`&&` の鎖・`bash -c '…'`・`$( … )`・`sudo`/`env`/`timeout`/`nice` などの後ろ・`eval`・shell の予約語・行の継続（`\` と改行）・`git -C dir` の中も見ます。heredoc の本文はデータとして扱います。
* git が長い option の省略（`--ha` は `--hard`）を受けることを知っており、設定された alias は `git config` で展開し、中が見えない `-c alias.*=` は拒みます。
* `git commit -m "… \`cmd\` …"` を捕まえます。バッククォートの中は git が起動する前に shell が実行するので、git の hook では見えません。`-F <file>` か一重引用符を使ってください。
* `safe-commit` は名指しした file だけを commit し（`git commit -- <paths>` は他のエージェントが stage した物を無視する。path は文字どおりで glob にしない）、新しい file は先に add し、そのうえで**commit を確かめます**。hook や同時の書き手が他の file を入れていたら exit 3 で知らせ、何も書き換えません。

## 任意: エージェントの道具の「実行前の hook」につなぐ

門と守りは `hook` の形を持ち、道具の呼び出し 1 回を JSON で stdin から読み、要るときだけ `deny` を出力します（Claude Code の `PreToolUse` の hook の形。似た hook を持つ道具なら同じ script を使えます）。設定の例は英語の README にあります。

hook の script を直したら、その場で `python3 -m py_compile <file>` を打ってください。起動に失敗する実行前の hook は全部の道具の呼び出しを止めることがあり、そうなるとセッションの中からは直せません。

## 範囲

* 門が絞るのは**自分の機械**に**自分が**掛ける負荷です。口座・資格情報・どのサービスの上限にも触れず、エージェントを自動で動かすこともしません。
* 受け箱は手元の dir です。機械の間で同期する（たとえば git の repo で）のは使う人の側で、時計のずれの見返しはそのためにあります。
* 作業ツリーの守りは誤りを捕まえる物で、安全の境界ではありません。文字を読むだけなので、走る時に組み立てる命令の名（`$G stash`）は、隣に git の subcommand の語があるときだけ報告します。
* Windows は対象外です（`fcntl` の file lock）。

## 試験

```sh
python3 -m pytest -q tests     # 107 件
bats tests/bats                # safe-commit の 7 件
```

上の設計の決まりにはそれぞれ試験があり、各試験は「コードの写しでその決まりをわざと壊すと落ちる」ことを確かめてあります
（例: 受け箱の床をしおりのように飛ばす・swap の total 0 を満杯と読む・`stash` の規則を外す・`safe-commit` の確かめを飛ばす）。
